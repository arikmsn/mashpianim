# עלייה לאוויר — צ׳קליסט לבעלים (נכתב 2026-11-09 בערב, לקראת 2026-11-10)

מסמך עבודה בעברית לבעל המערכת. מה לעשות בלוחות הבקרה (Vercel, Supabase, GreenAPI), מה אני עושה אחר כך בקוד,
ומה לקבל מסאמיט (SUMIT) בשיחה. שום סוד לא נכנס לכאן ולא לצ׳אט: מפתחות וסיסמאות נכנסים ישירות ל-Vercel
(Project → Settings → Environment Variables) או נשארים אצלך.

## 1. Vercel — מעבר ל-Pro (20$ לחודש למושב)

**למה:** תוכנית Hobby אסורה לשימוש מסחרי לפי תנאי Vercel, שומרת לוגים שעה אחת בלבד, מגבילה קרון לפעם ביום
ומגבילה את משך הפונקציות. אנחנו עולים לאוויר עם משתמשים אמיתיים — חייבים Pro.

**מה לעשות (אתה):**
1. vercel.com → הצוות `arikmsns-projects` → Settings → Billing → **Upgrade to Pro**. כרטיס אשראי של העסק.
2. להשאיר מושב אחד (שלך). לי לא צריך מושב — אני עובד דרך ה-MCP שכבר מחובר.
3. אחרי השדרוג: Project `mashpianim` → Settings → Functions: לוודא **Fluid Compute** דולק (ברירת מחדל) ו-**Function Region = cdg1 (Paris)** (כבר מוגדר ב-`vercel.json`).

**מה אני עושה אחר כך (בקוד, עם אישורך לדחיפה):**
- הקרון של הדדליינים (`/api/cron/deadlines`) מפעם ביום ל-**כל 15 דקות** — כך סרטון שלא נענה בחלון הבדיקה נסגר בזמן אמת ולא עד הבוקר.
- אין צורך בשינוי אחר; הקוד כבר רץ בפריז ליד בסיס הנתונים.

**מה לא צריך:** Observability Plus, Password Protection, מושבים נוספים.

## 2. Supabase — מעבר ל-Pro (25$ לחודש + קרדיט מחשוב 10$ כלול)

**למה:** ב-Free הפרויקט מושהה אחרי שבוע ללא פעילות, אין גיבויים, אחסון הקבצים מוגבל ל-1 GB (סרטוני תיק
עבודות של 20–50 MB יגמרו אותו תוך ימים), והתעבורה החוצה ל-5 GB. Pro: 8 GB בסיס נתונים, **100 GB אחסון קבצים**,
250 GB תעבורה, **גיבוי יומי ל-7 ימים**, בלי השהיה, תמיכה במייל.

**מה לעשות (אתה):**
1. supabase.com → Organization (ktrmynnqdznkkajwpufv) → Billing → **Upgrade to Pro**. מספיק פעם אחת לארגון.
2. Compute: להשאיר **Micro** (כלול בקרדיט). אם נראה איטיות אחרי כמה ימים עם משתמשים — Small (15$) הוא הצעד הבא, לא לפני.
3. **לא** להוסיף PITR (100$ לחודש) בשלב הזה; הגיבוי היומי מספיק.
4. Project → Storage → Settings → **Global file size limit: 150 MB** (היום 50 MB בגלל Free).
5. Project → Settings → General: לוודא שהפרויקט לא מסומן להשהיה (ב-Pro זה נעלם אוטומטית).

**מה אני עושה אחר כך:**
- מעלה את תקרת הסרטון באפליקציה `MAX_VIDEO_MB` מ-50 ל-**150** (כ-2 דקות ב-1080p) ומעדכן את הטקסט למשתמשים.
- מעדכן את ספי ההתראה של מד הקיבולת במנהל (70% / 90%) לנפחים של Pro.
- בודק שה-cron של הקיבולת עדיין מדווח נכון.

**לקרוא ממך אחרי השדרוג:** "סיימתי את Supabase Pro ואת תקרת 150" — ואני מריץ את השינויים ודוחף.

## 5. סאמיט (SUMIT) — סליקה + חשבוניות: מה לקבל בשיחה

**איפה אנחנו היום:** המערכת בנויה עם שכבת מתאמים (adapters) לתשלומים ולחשבוניות, אבל שתיהן עדיין סטאב:
מאז 10.11 בלילה (לבקשתך): **כל עסק חדש מתחיל עם 0 סרטונים**; לחיצה על "רכישת סרטונים" (בעמוד הבית של העסק, בפרופיל ובאישור התאמה) מציגה "אנא פנו אלינו בצור קשר (שבתוך האתר) לקבלת גישה." ופותחת את טופס יצירת הקשר עם הנושא "רכישת סרטונים — בקשת גישה"; הפנייה מגיעה אליך כהתראה במנהל (פניות) ואתה מטעין את הסרטונים ב"עסקים". טבלת `transactions`
(סכום, קרדיטים, אמצעי תשלום, אסמכתה, סטטוס) כבר קיימת. החיבור לסאמיט הוא עבודה של יום-יומיים אצלי אחרי
שיש גישה.

**מה SUMIT מציעים ואיך זה מתחבר אצלנו (מתוך ה-API שלהם, api.sumit.co.il):**
- זיהוי: כל קריאה נושאת `Credentials { CompanyID, APIKey }` — שני ערכים שמקבלים בממשק סאמיט (הגדרות → API).
- סליקה: דף תשלום מתארח (`/creditguy/gateway/beginredirect/` — אנחנו מפנים את העסק לדף של סאמיט והוא חוזר
  אלינו עם מזהה עסקה שאותו אנחנו מאמתים ב-`/creditguy/gateway/gettransaction/`) או חיוב ישיר בטוקן
  (`/creditguy/vault/tokenizesingleuse/` + `/creditguy/gateway/transaction/`). **ההמלצה שלי: דף תשלום מתארח** —
  פרטי הכרטיס לא עוברים אצלנו בכלל, ואין לנו חובות PCI.
- חשבוניות: `/accounting/customers/create/` (לקוח = העסק), `/accounting/documents/create/` (חשבונית מס/קבלה
  על הרכישה), `/accounting/documents/send/` (שליחה במייל), `/accounting/documents/cancel/` (זיכוי בביטול).

**לבקש ולברר בשיחה:**
1. **שני ערכים לממשק**: `CompanyID` ו-`APIKey` של העסק שלך — **לא לשלוח לי**; מכניסים ישירות ל-Vercel כ-
   `SUMIT_COMPANY_ID` ו-`SUMIT_API_KEY` (Production). אני אשתמש בשמות האלה.
2. **מודול הסליקה פעיל?** סליקה בסאמיט דורשת חוזה סליקה (ישיר מול חברת אשראי או דרכם). לברר: מה העמלה, כמה
   ימים עד הכסף, האם 3-D Secure נתמך, האם צריך "מסוף" נפרד.
3. **דף תשלום מתארח**: האם קיים ואיך מפעילים (מה ה-RedirectURL/ReturnURL שצריך לרשום אצלם —
   `https://www.mashpian.online/api/payments/sumit/return`), ואיך מקבלים את תוצאת העסקה בחזרה (פרמטרים
   בחזרה / webhook). אם יש webhook — איזו כתובת לרשום ואיך הוא חתום.
4. **סביבת בדיקות**: האם יש חשבון/מצב Sandbox וכרטיסי בדיקה, כדי שנבדוק בלי לחייב כרטיס אמיתי.
5. **חשבוניות**: סוג המסמך שיופק אוטומטית (חשבונית מס/קבלה), שהמחירים אצלנו כוללים מע״מ, שליחה אוטומטית
   במייל ללקוח, ומה קורה בהחזר (חשבונית זיכוי).
6. **פרטי העסק שלך לחשבונית** (אלה כן תעביר לי, לא סודיים): שם משפטי, מספר עוסק/ח.פ, כתובת, לוגו —
   הם נכנסים גם לתנאי השירות כשתרצה.
7. **חבילות הקרדיטים ומחיריהן** (למשל 5/10/20 סרטונים) — כדי שאבנה את מסך הרכישה. מדיניות הביטולים שלנו
   (14 יום לחבילה שלא נוצלה) כבר מתאימה לחשבונית זיכוי.

**אחרי השיחה:** אני מממש `SumitPaymentProvider` + `SumitInvoiceProvider` במתאמים הקיימים, מסך רכישה עם
החבילות, נתיב חזרה שמאמת את העסקה ומטעין קרדיטים, ושליחת חשבונית — ונבדוק בסנדבוקס לפני שמחליפים את טופס
יצירת הקשר.
